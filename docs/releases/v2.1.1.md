# Milesight Dashboard v2.1.1

Choose **Firebase cloud** or **DuckDB local** in `/setup`, save the storage choice with the administrator token, and restart. Local mode stores accounts, workspace settings, credentials, device metadata, telemetry, history, and command records in `milesight.duckdb` in the runtime directory (Docker: `/data/milesight.duckdb`). It does not require Firebase credentials, Firebase Authentication, or the browser Firebase SDK.

Local account registration requires the administrator setup token and a password of at least ten characters. Passwords use salted scrypt hashes. Local sessions expire after 24 hours and are cleared by a server restart. Google/Microsoft sign-in and email password resets are available only in Firebase mode. Local sign-in runs over the same server connection as the dashboard; use HTTPS for remote access.

Telegram Settings now offers **Command buttons (no AI)** or **Gemini AI**, independently of storage. Commands include `/devices`, `/latest`, `/status`, `/menu`, `/help`, and owner-only `/system` in private chats. Existing workspace membership and session checks apply before sensor commands. Telegram itself requires internet access; Gemini mode also calls Google's service and sends a summary of workspace readings.

Settings includes authenticated system status: disk capacity/free space, DuckDB file plus WAL size, memory visible to the server/container, and app RAM. These are server resources, not the visitor's computer. A cgroup v2 memory limit is shown when available. The mounted filesystem's capacity may be shared by other applications.

Storage changes require a restart. They select separate databases and do not migrate accounts or readings. Back up `/data` before changes; stop the server before copying a DuckDB database and its WAL. Run one dashboard process per DuckDB file. The existing approximate 1 GB per-workspace history retention policy remains in effect; physical file size can differ from this estimate.

Validation includes real DuckDB persistence/transaction tests, local API authentication and access checks, Telegram command formatting, and a local server/MQTT ingestion integration test. Existing Firebase rules are unchanged.
